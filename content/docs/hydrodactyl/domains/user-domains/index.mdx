---
title: User Domains
description: Let server owners point their own Cloudflare domain at their Minecraft server.
---

Custom domains let server owners point a domain they own, on their own Cloudflare
account, at their Minecraft server. For example, `play.example.com`. Hydrodactyl
creates the DNS records immediately and keeps them up to date when the server's
address or port changes.

Custom domains work alongside the panel's regular subdomains (the domains an
administrator adds in **Admin -> Settings -> Domains**). A server can have one
subdomain and one custom domain at the same time.

<Callout type="info">
  Custom user domains are currently only available for Minecraft servers and only supports
  Cloudflare.
</Callout>

## What You Need

- A Minecraft server using an egg with the `subdomain_minecraft` and
  `user_domains` features
- A domain on a Cloudflare account you control
- An administrator who has enabled **Custom Domains** for the server's owner

## Enabling Custom Domains

A server can only use a custom domain when **all four** of these settings allow
it. If any one of them is off, custom domains are off for that server.

| Where  | Setting                                                                                      | Default                           |
| ------ | -------------------------------------------------------------------------------------------- | --------------------------------- |
| Egg    | **Admin -> Nests -> Egg -> Features** must include both `subdomain_minecraft` and `user_domains` | On for the bundled Minecraft eggs |
| Node   | **Admin -> Nodes -> Your Node -> Custom Domains**                                            | On                                |
| Server | **Admin -> Servers -> Your Server -> Build -> Custom Domains**                               | On                                |
| User   | **Admin -> Users -> the server's owner -> Custom Domains**                                   | **Off**                           |

In practice, an administrator only needs to set **Custom Domains** to **Yes** for
each user who should be allowed to use them. The node and server settings are for
turning custom domains off in specific places.

### Supported Games

Only Minecraft servers (eggs with the `subdomain_minecraft` feature) can use custom
domains. Other games such as TeamSpeak, Rust, or Vintage Story don't get custom
domains, even if `user_domains` is added to their egg.

### Existing Eggs

The bundled Minecraft eggs (Paper, Purpur, Fabric, Forge, NeoForge, Quilt, Folia,
Sponge, Vanilla, BungeeCord, Velocity, Waterfall, and Limbo) include `user_domains`
when freshly seeded.

<Callout type="warn">
  Eggs that are already installed or were imported need `user_domains` added to
  their **Features** field by hand. See [Egg
  Features](/docs/hydrodactyl/config/egg-features).
</Callout>

## Adding A Custom Domain

1. Open your server and go to **Network**, then select **Domains**.
1. In the **Domain Management** window, scroll to the **Custom Domain** section.
1. Fill in:

   - **Domain**: the full address players will use, for example
     `play.example.com`, `mc.example.com`, or `example.com`
   - **Allocations**: the `ip:port` the domain should point to. This field only
     appears when the server has more than one allocation, and defaults to the
     primary allocation.
   - **Cloudflare API Token**: a token with `Zone` -> `DNS` -> `Edit` permission

1. Select **Add Domain**.

The records are created immediately. Once DNS propagates (usually a minute or two),
players can join using the domain without typing a port.

### Create A Cloudflare Token

Select **here** in the **Cloudflare API Token** field's label to open Cloudflare
with the correct permission already selected:

- `Zone` -> `DNS` -> `Edit`

You can scope the token to a single zone or allow all zones. Create the token,
copy it, and paste it into the field.

<Callout type="info">
  Scope the token to only the domain you're using, so it can't change anything
  else on your Cloudflare account.
</Callout>

## Record Behavior

For `play.example.com` pointing at `203.0.113.5:25566`, Hydrodactyl creates:

| Type | Name                               | Points to                        | Comments                                                    |
| ---- | ---------------------------------- | -------------------------------- |-------------------------------------------------------------|
| A    | `play.example.com`                 | `203.0.113.5`                    | Autogenerated By Hydrodactyl Panel (changes with panel name)|
| SRV  | `_minecraft._tcp.play.example.com` | `play.example.com`, port `25566` | Autogenerated By Hydrodactyl Panel (Changes with panel name)|

Both records use a 5 minute TTL and include the comment **"Autogenerated by
&lt;your panel's name&gt;"** so you can identify them in the Cloudflare dashboard.

If **Domain by Allocation Alias** is enabled on the node and the allocation has an
alias, the alias is published instead of the allocation IP. See [Cloudflare
Subdomains](/docs/hydrodactyl/domains/subdomains/cloudflare#configure-the-node-and-allocations).

### Automatic Updates

| When                                            | What happens                                                        |
| ----------------------------------------------- | ------------------------------------------------------------------- |
| The allocation's IP, alias, or port changes     | Records are updated to match                                        |
| The server's primary allocation changes         | Records are updated, if the domain follows the primary allocation   |
| The server is switched to a non-Minecraft egg   | The custom domain and its records are deleted                       |
| The server is deleted                           | The custom domain and its records are deleted                       |

## Editing A Custom Domain

1. Select **Edit Domain** on the **Current Custom Domain** card.
1. Change either of the following:

   - The part in front of your domain, for example `play` -> `mc`. Leave it empty
     to use `example.com` itself.
   - The allocation the domain points to.

1. Select **Save Changes**.

The new records are created before the old ones are removed, so the domain keeps
working while you make the change.

<Callout type="info">
  You can't switch to a different Cloudflare domain by editing. Remove the custom
  domain and add the new one instead.
</Callout>

## Removing A Custom Domain

Select **Delete Domain** and confirm. The custom domain and its records are deleted
from Cloudflare.

## Subuser Permissions

These permissions are listed under **Allocations** in a subuser's permissions:

| Permission                        | Allows                                         |
| --------------------------------- | ---------------------------------------------- |
| `allocation.custom_domain_read`   | Seeing the server's custom domain              |
| `allocation.custom_domain_update` | Adding, editing, and removing the custom domain |

Subusers also need `allocation.read` to open the **Domain Management** window.

Whether custom domains are available depends on the server **owner's** Custom
Domains setting, not the subuser's.

## Limits

- One custom domain per server.
- A domain can only be used by one server across the whole panel.
- The domain must not already have an A, AAAA, or CNAME record in Cloudflare.
  Delete the existing record there first.
- Only Cloudflare is supported.

## Security

- The API token is stored encrypted and is never shown again after you save it,
  not even to administrators.
- The token is only used to manage the DNS records for that one domain.

## Troubleshooting

### `Cloudflare rejected this API token`

The token doesn't have `Zone` -> `DNS` -> `Edit`. Create a new token using the link
in the form and try again.

### `Could not find a Cloudflare domain for ... with this API token`

The domain isn't on that Cloudflare account, or the token isn't scoped to it.

### `... already has a A record in Cloudflare`

Delete the existing A, AAAA, or CNAME record for that name in Cloudflare, then try
again.

### `This server already has a custom domain`

Each server can only have one custom domain. Edit or remove the existing one first.

### `This domain is already pointed at a server`

Another server on the panel already uses this domain.

### `Custom domains are not enabled for this server`

One of the four settings in [Enabling Custom Domains](#enabling-custom-domains) is
off. Ask your administrator to check them.

### `Cloudflare rejected the API token saved for this domain`

The saved token was deleted or has expired in Cloudflare. Remove the custom domain
and add it again with a new token.

<Callout type="warn">
  If the saved token no longer works, removing the custom domain only removes it
  from the panel. Hydrodactyl can't delete the records in Cloudflare anymore, so
  delete them there by hand.
</Callout>
